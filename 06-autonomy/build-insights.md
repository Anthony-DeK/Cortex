# Build Insights: Cortex PM Chief-of-Staff Agent

> Module 6 · ★ Deliverable 4, what you learned building it
>
> ✅ **What this validates:** you can reflect on what building it taught you, by the end you'll have proven the friction, the learning, and the aha that changes how you'd design your next agent.

## Friction

The build itself went really well and didn't fight me much. The friction was the evals: they took most of the time. Approving each artifact for a golden set is really time-consuming.

## Learning

1. Building the agent is easy; the evals work is tedious and takes most of the time.
2. That tedious work is what guarantees quality: a golden set of approved outputs is what keeps quality high at a reasonable cost to serve.
3. Designing agents is both really fun and essential. Without going through this process, it's easy to lose sight of why we do what we do when building one.

## Aha moment

An agent is a delicate balance between a prompt, a skill, a tool and evals. Some agents could just be skills, but you need to tell the agent to use that skill, or it never will.

## What you'd do differently

I wouldn't necessarily build Cortex differently. Instead, I'd start by mapping all the use cases I'd want an agent for at my job, and work out whether and how an agent could do each one.
